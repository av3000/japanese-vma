# Issue tracker: GitHub

Issues and planning tickets for this repo live as GitHub issues in `av3000/japanese-vma`.

## Conventions

- Create issues in the GitHub repository, not in GitLab.
- Treat GitHub as the source of truth for planning and execution tracking unless a future repo decision changes this.
- When a local planning document is turned into tracker work, publish it to GitHub and link the resulting issue numbers back into the doc when useful.

## Repository

- Primary tracker repo: `av3000/japanese-vma`
- Local clone remotes may include both GitHub and GitLab, but issue publication should target GitHub by default.

## When a skill says "publish to the issue tracker"

Create a GitHub issue in `av3000/japanese-vma`.
