# Writing stories

## File and title

- Put `<Component>.stories.tsx` next to the component.
- Set an explicit `title` in the sidebar hierarchy: `Shared/…`, `UI/…`, `System/…`, `Features/<Domain>/…` or `Pages/…`. Moving a file then never renames its stories.
  - Feature domains: `Navigation`, `Articles`, `Catalogues`, `Community`, `Comments`, `Auth`, `Dashboard`, `Flashcards`, `Homepage`, `Japanese`, `LibraryCards`, `Realtime`.
- Type the meta with `satisfies Meta<typeof Component>`, and stories with `StoryObj<typeof meta>`. No `@ts-ignore`.

## Args

- Callbacks are `fn()` spies from `storybook/test`, so a `play` can assert they were called.
- Defaults live in the meta's `args`.
- Variant option lists come from the component's own exported constants, never a copied list.

## App contexts come from parameters

The global decorators provide React Query, the router, auth and the socket, nested as in `App.tsx`. Never mount the real providers or import from `providers/contexts/` in a story.

| Parameter | Shape | Default |
|---|---|---|
| `auth` | `'guest' \| 'loading' \| 'member'`, or fields to override. Passing a `user` signs that user in: `{ user: { ...users.member, id: OWNER_ID } }` | The toolbar's Viewer (guest) |
| `socket` | `'unconfigured' \| 'connecting' \| 'connected' \| 'reconnecting' \| 'failed'`, or fields to override, such as a fake `echo` | The toolbar's Socket (connected) |
| `router` | `{ initialEntries?: ['/kanjis?page=2'], path?: '/kanji/:kanji_id' }`. Set `path` when the component reads `useParams` | `{ initialEntries: ['/'] }` |
| `seeds` | `QuerySeed[]`: query keys and the data the cache already holds. Build keys with the generated `get…QueryKey` helpers and the `pageSeed`/`infiniteSeed` helpers from `@/storybook/decorators` | `[]` |

- A story that is *about* a viewer or a connection state (`Guest`, `Owner`, `Polling`) pins it with `parameters.auth` or `parameters.socket`. Leave the rest unpinned, so the toolbar can flip them.
- Viewers come from `@/storybook/fixtures/users`: `users.member` is the default member, and `users.other` is a second one for owner-versus-visitor stories.
- The auth actions are spies in `authSpies` (`login`, `register`, `logout`, `clearSessionExpired`), cleared before every story. A `play` asserts on them directly: `expect(authSpies.logout).toHaveBeenCalled()`.
- Each story gets a fresh query client: no retries, no refetch on focus, and seeded data never goes stale. A seeded story fetches nothing unless it asks for new data (another page, another filter). Without a backend, that request fails and shows the component's real error state.

## Viewports

Pick a preset by name: `globals: { viewport: { value: 'xs' } }`. The presets are `xs` 360, `sm` 768, `md` 1024, `lg` 1320 and `xl` 1600.

## Play functions

- Assert on roles and accessible names (`getByRole('button', { name: 'Save' })`), never class names or DOM structure.
- Use `await expect(…).toBeVisible()` or `waitFor` for anything animated or async, never fixed sleeps.
- Dialogs render into `document.body`; query them with `within(document.body)`.

## Fixtures

Keep fixtures beside the domain that owns them (`components/features/<domain>/fixtures.ts`), typed from the Orval models in `@/api/generated/model`, so a schema change breaks `npm run typecheck` rather than a story. Move one to `src/storybook/fixtures/` only once a second domain needs it.
